## Planned fixture and evidence setup

Use the discovery isolation checklist before any future run. Freeze the seed revision, clock, time zone and browser build. Reset to the original seed before independent variants, especially edits, cancellations, deletions, restores and sync conflicts. For output branches capture the generated artifact or intercepted arguments, never send a message or invoke a real printer. For sync substitute in-process responses at the transport boundary; assert attempted calls and their order without contacting an endpoint. Stop if isolation cannot be verified.

- **E:** Empty disposable database, sync off.
- **B:** One named customer with opening due, a separate same-name customer with a distinct ID, and a walk-in. - **P:** Two suppliers with different rates for one matched product, another product with no supplier rate, an unmatched PO item and nonzero opening stock. Order five cases of the matched item; use two dated receipts at different prices, entering the later document date first. Include same-day lot variants, a shortage and a physical adjustment. Record stock in a common unit alongside case quantities.
- **T:** Synthetic business and party states, products with defaults and overrides, HSN and cess, one crate and fractional GST-inclusive values. No real tax or contact data.
- **X:** Disposable snapshot/revision variants, malformed import, distinct local and mock-remote data, fake device labels, intercepted output and scripted transport failures. No live configuration or accounts.

### localStorage mirror cutoff (NOT RUN)

**L01-15 (source only):** Use independent synthetic DB copies with the same starting revision. Adjust an inert padding field so `JSON.stringify(DB)` inside `saveDB()`, after the revision increment, yields a nonempty string with JavaScript `.length` of 4,499,999 in one variant and 4,500,000 in the other. Use the serialized string's UTF-16 code unit count, not file bytes or browser quota (L717-725).

- **Immediately below the cutoff:** Expect an attempted `localStorage.setItem(LS_KEY, str)` and an attempted `idbSet("kv", "db", DB)`.
- **Exactly at the cutoff:** Expect no mirror write attempt because the guard is strictly `str.length < 4500000`. Expect the IndexedDB write attempt to proceed because it is outside that guard (L725-733).

Capture each write attempt at its call boundary. In a separate readback check, seed a distinct existing mirror at `LS_KEY` before each save, let writes settle, and verify what each store contains. At the cutoff, expect the existing mirror to remain unchanged: `saveDB()` skips the mirror write and does not clear the slot. An attempted call is not proof of a durable write (L725-733).

**Reload at the cutoff (source only):** On independent synthetic copies, seed valid, distinguishable older records in both stores, with the localStorage mirror's revision higher than the old IndexedDB revision. Give the new in-memory copy a third marker and set its starting revision so that the increment in `saveDB()` puts it above both stored revisions. Keep the serialized string at the exact cutoff after that increment. Wait for the original write outcome, capture the save warning separately, read back both stores before reloading, and then capture the selected marker independently of any save triggered by reload (L641-667, L684-704, L717-734).

- **IndexedDB write completes (NOT RUN):** Expect no save warning from this attempt. Readback should show the new higher revision in IndexedDB and the unchanged mirror. On reload, expect `loadDB()` to select the new IndexedDB marker.
- **IndexedDB write fails (NOT RUN):** Abort only the original IndexedDB write transaction so it leaves the old record intact and subsequent reads still work. With no mirror write, expect **Could not save — use folder/cloud backup!**. Readback should show both older records unchanged. On reload, expect `loadDB()` to select the localStorage marker because its revision is higher than the old IndexedDB revision.
