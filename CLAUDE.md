# ALM builder rules
- Build to `docs/PRD.md`. Treat the verified `ALM_Business_Manager.html` baseline as the behavioral and visual oracle; do not change it to make the port look correct. Trace each implemented action and test to the inventory. Preserve secondary and conditional actions, not just navigation tabs.
- Phase 1 is discovery only: no product implementation or production changes. Inspect live systems only through explicitly authorized read-only channels. Run legacy walkthroughs against isolated fixtures with live integrations disabled or redirected. Use a separate hosted test project after implementation approval; production cutover needs a separate written approval.
- Keep domain logic in a typed Rust core and authoritative shared mutations behind Supabase's server-side transaction boundary. Presentation code may render and route input but must not calculate or authorize business outcomes. Validate at boundaries; keep UI, storage, sync, and domain code separate. Use typed money, quantities, dates, identifiers, and explicit rounding; prove that rounding and reporting dates match the legacy outputs rather than assuming they do.
- Trace bill edits and cancellations, estimates, partial receipts, FIFO layers and valuation, crates and godown movements, GST breakdowns, udhaar and receipts, cash-book entries, and backup/restore together with their linked effects. Do not infer invoice series, tax treatment, historical recalculation, or stock/location boundaries from the single-entity answer. Record ambiguous or suspect legacy behavior; get a decision before changing it.
- Treat local SQLite as a scoped cache and durable provisional-order store, never the authority for posted sales. Give confirmation a durable request identity, check current terms and permission on the server, and keep all posting effects atomic. Test restart, reconnect, competing devices, stale terms, and loss of a successful response.
- Enforce access using Supabase policies, grants, and restricted data and mutation interfaces; hiding UI is not authorization. Use only staff-authorized projections on staff devices. Check account switching, revocation on reconnect, and cache separation; do not provision staff devices with owner-only data. Keep administrative credentials, raw production records, and unrestricted backups out of clients, Git, transcripts, and ordinary test artifacts.
- Test with frozen legacy fixtures, differential assertions, output comparisons, hosted role and concurrency checks, installed-app walkthroughs, and migration/rollback rehearsals. Compare bill-image layout and content before relying on the WhatsApp handoff. Check actual target platforms; a desktop browser or emulator alone does not establish installed-device acceptance.
- No fabricated numbers, no tuning thresholds or weakening tests to pass, and no presenting development runs as real results. Record every reported number in `docs/RESULTS.md`. Report a miss as a failure and missing evidence as blocked or not run. Only the owner can decide what to do about a missed criterion; do not propose loosening it to clear a phase.

## Running under agent-bridge

These rules come from the tool that runs this project; the project's own rules are above.

- **Messages are labelled.** `[owner]`: the owner's own words; binding. `[planner]`: plan changes and the
  first instruction. `[supervisor]`: the review of your last turn and your next instruction. `[bridge]`:
  automated notes from the tool; they state facts and never add scope.
- **Headless.** Nobody can answer an interactive prompt. Never use a question or ask-user tool. Put every
  question under `DECISIONS NEEDED:` in your end-of-turn report, do all the unblocked work you can first,
  then end the turn.
- **End-of-turn report.** What you did, with commits and command output as evidence; then
  `DECISIONS NEEDED:` (or none) and a `PROCEEDING:` line with the next concrete step.
- **Waiting.** To wait for a job or a time, end your report with one line, `WAIT FOR PID <n>`,
  `WAIT FOR FILE <path>` or `WAIT UNTIL <ISO-8601 time>`. The bridge sleeps without calling any model and
  wakes you when it is over. Never poll in a loop inside your turn. Long jobs run in the background: record
  their command, pid and log in the worklog.
- **The contract.** docs/PRD.md and CLAUDE.md are the approved plan.
  Never edit them, or `bridge.toml`; propose changes under `DECISIONS NEEDED:`. Requirements and phases
  the bridge lists as blocked are off limits until the owner settles them.
- **Records.** Decisions go in docs/DECISIONS.md as `## DEC-NNN <title>` with `- Decided by:` and
  `- Status:` lines; a decision you make that the supervisor approved has
  `Decided by: builder, approved by the supervisor`. Open items and OWNER-BLOCKED items go in
  docs/OPEN.md. Every number you report gets a row in docs/RESULTS.md: id, what was
  measured, value, kind (`development` or `real`, as the PRD defines them), run id or artifact, commit.
  The bridge appends some entries itself (marked as recorded by agent-bridge); commit them with your next
  commit and never edit their status lines.
- **Honesty.** No fabricated numbers, no placeholder results, no tuning thresholds to make something pass,
  no development run presented as a real result. A failure is reported as a failure.
- **Commits.** Commit each coherent unit of work, with explicit paths, using the repo's own author. No
  `Co-Authored-By` or AI-attribution lines. Never rewrite history or force-push. Never push, and never add a remote.
